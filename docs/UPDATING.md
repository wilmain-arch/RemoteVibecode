# Обновление

[← Главная](../README.md)

Версия комплекта (`bundle-v…`) объединяет независимо версионируемые APK, агент и ретранслятор. Состав всегда смотрите в описании релиза. Обновляйте указанные там компоненты; сервер не требуется переустанавливать при каждом изменении интерфейса телефона.

## Перед обновлением

Дождитесь завершения задач и отправки очереди сообщений. Скачайте файлы одного комплекта из [Releases](https://github.com/wilmain-arch/RemoteVibecode/releases/latest). Для проверки файлов используйте `SHA256SUMS.txt`: Linux — `sha256sum -c SHA256SUMS.txt`, Windows — `Get-FileHash .\RemoteVibecodeAgent.exe -Algorithm SHA256` и сравнение с файлом сумм. Проверяйте только скачанные файлы; отсутствие остальных вызовет сообщение об ошибке проверки.

## ПК

- **Windows:** выберите «Выйти» в меню значка агента в трее. Закрытие окна лишь скрывает его. Замените EXE и запустите новую версию.
- **Arch:** выйдите из агента через трей, выполните `sudo pacman -U ./remotevibecode-agent-ВЕРСИЯ-1-any.pkg.tar.zst`, затем запустите `remotevibecode-agent`.

Установка пакета сама по себе не обновляет уже запущенный процесс. Настройки сохраняются в каталоге RemoteVibecode профиля пользователя.

## Сервер

Если релиз меняет ретранслятор, выполните `sudo apt install ./remotevibecode-relay_ВЕРСИЯ_all.deb` и `sudo systemctl restart remotevibecode-relay`. Убедитесь, что служба активна. Секрет и сертификат сохраняются при обновлении. Не выполняйте purge для обычного обновления.

## Телефон

Установите APK поверх существующего приложения. Не удаляйте приложение и не очищайте его данные: это удалит локальную привязку и черновики. При ошибке несовместимой подписи не удаляйте приложение сразу — сохраните нужные данные и сообщите об ошибке.

Текущие APK подписываются ключом разработки. Для совместимых обновлений необходим тот же ключ подписи; переход на другой ключ требует отдельно объявленной миграции.

## После обновления

Проверьте список чатов, отправку сообщения и получение ответа. При обновлении Codex Desktop перезапустите агент после завершения задач. Если появилась ошибка модели, заново выберите модель из актуального списка.

## Обновление из приложения

Начиная с Android 0.10.0 и агента 0.2.2 обновления можно устанавливать из интерфейса. Эту первую версию нужно установить обычным способом.

### Android

Откройте меню проектов → **Обновления**. До привязки телефона эта кнопка находится в верхней панели. Проверка выполняется при запуске и затем раз в сутки, пока приложение работает; вручную — кнопкой **Проверить обновления**.

1. Нажмите **Скачать обновление**. Во время скачивания отображается прогресс; его можно отменить.
2. После проверки нажмите **Установить обновление**.
3. Если Android попросит разрешение, включите установку приложений из этого источника и вернитесь в RemoteVibecode.
4. Подтвердите обновление в системном установщике. Если отменили установку, её можно открыть повторно.

Приложение проверяет подпись манифеста, размер и SHA-256 файла, версию APK, идентификатор приложения и сертификат подписи. При несовпадении установка блокируется. Настройки и привязка сохраняются. После закрытия процесса скачивание не продолжается: откройте раздел и скачайте файл снова.

### Агент Windows

Откройте **Обновления** → **Скачать обновление** → **Установить**. Агент дождётся окончания задач и очереди сообщений. Ожидание можно отменить. Проверка завершения задач должна пройти успешно: при недоступном Codex агент не закрывается.

Отдельный процесс обновления заменит EXE и запустит новую версию. Если она не подтвердит запуск в течение минуты, обновлятор восстановит прежний EXE. Результат появится на вкладке обновлений; журнал находится в папке настроек `updates/update.log`. Сохраняется файл `.previous.exe` рядом с основным EXE. Каталог EXE должен быть доступен пользователю для записи: храните агент в своей папке, а не в `Program Files`.

Перед установкой сохраните работу в Codex Desktop и не запускайте там новые задачи до перезапуска агента. Агент блокирует новые отправки через собственный мост на время установки, но не управляет кнопками отдельного Desktop приложения.

### Агент Arch

Откройте тот же раздел. Установка запускается через `pacman -U`; права администратора запрашивает `polkit`. Нужен работающий графический агент авторизации polkit вашей среды рабочего стола. Данные приложения остаются в домашней папке. После отмены запроса прав или ошибки агент запускается снова. Для запуска из исходников доступна проверка и скачивание, а обновление выполняется через Git.

### Источник и совместимость

Источник — только последний стабильный GitHub Release проекта. Проверка не использует секрет ретранслятора и не зависит от соединения с ПК. Доступность релиза обозначается в меню; автоматической установки нет. При недоступности GitHub работа чата продолжается. Версии компонентов сравниваются отдельно. Несовместимая версия протокола требует ручного обновления компонентов по инструкции выпуска.

Ретранслятор обновляется администратором сервера по инструкции выше. Приложение не получает root-доступ к серверу и не переустанавливает его службы.
