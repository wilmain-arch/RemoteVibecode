# Архитектура клиента 0.7

## Источник истины

Codex app-server остаётся источником чатов, модели, статуса и истории. Мост не копирует историю в собственную базу. Телефон хранит выбранный чат, черновик, локальную очередь и токен устройства. Мост хранит сопряжение, очередь и ожидающие файлы. Файлы передаются по HTTPS с проверкой сертификата и SHA-256.

## Карта функций

| Функция | app-server | API моста | Android |
| --- | --- | --- | --- |
| Проекты | `project/list`, `thread/list`, `thread/metadata/update` | `/api/projects`, `/api/threads/project` | Группы, переход и перемещение чата |
| Чаты | `thread/list` с курсором | `/api/threads` | Поиск и выбор |
| Новый чат | `thread/start` при первой отправке | `/api/threads` POST | Действие в шапке |
| История/статус | `thread/read` | `/api/history`, `/api/status`, `/api/limits` | Лента и ход работы |
| Модели/усилие | `model/list`, `turn/start` overrides | `/api/models`, `/api/send` | Нижний лист выбора |
| Отправка и очередь | `turn/start`, активный writer | `/api/send`, `/api/messages/cancel` | Локальная очередь с ID и отмена |
| Файлы | `cwd` выбранного чата, локальные пути и image input | `/api/workspace`, `/api/workspace/preview`, `/api/workspace/download`, `/api/workspace/image`, `/api/chat/image`, `/api/outbox/image`, `/api/upload`, `/api/upload/cancel`, `/api/outbox`, `/api/download` | Экран проекта и передачи, SAF picker, предпросмотр и сохранение |

## Принципы

1. Все запросы после сопряжения требуют bearer-токен; TLS-пин проверяется приложением. Ежедневного входа нет.
2. Выбранный чат передаётся в каждом запросе отправки и хранится в локальной очереди, чтобы переключение списка не направило сообщение в другой чат.
3. Модель и усилие берутся из `model/list`; сервер проверяет комбинацию перед `turn/start`. Без выбора сохраняются настройки чата.
4. Показать лишь опубликованные app-server сводки размышления (`summary`) и действия инструментов. Сырой `content` reasoning не выдавать через мост.
5. App-server запускается по требованию и завершается после 15 секунд простоя. При опросе открытого чата процесс остаётся активным.
6. Список проектов и их порядок берутся из `project/list`. Назначение чата сохраняется через `thread/metadata/update`; для старых чатов поддерживается сопоставление с локальным состоянием Desktop.
7. Пустой чат сначала существует как черновик моста. `thread/start` и первый `turn/start` выполняются в одной сессии app-server: иначе пустой чат пропадает при его завершении после 15 секунд простоя. Ответ на первую отправку содержит постоянный ID, который телефон сохраняет вместо ID черновика.

## Состояния интерфейса

Нет сопряжения → одноразовое QR-подключение. Есть токен, нет сети → сохранённый чат и черновик, отправка в локальную очередь. Есть сеть → обновление статуса/истории. Чат занят → сообщение в очереди моста; модель/усилие привязаны к конкретному сообщению. Смена чата → загрузка его истории и статуса без смешивания очередей.

## Границы первой итерации

Полный Desktop содержит удалённые хосты, рабочие деревья, разрешения, review, голос и другие сценарии. Их нельзя объявлять готовыми одной оболочкой чата. В этой итерации реализуются перечисленные пользователем функции разговора и навигации; дополнительные Desktop-сценарии получают отдельные API и экраны после проверки протокола.
