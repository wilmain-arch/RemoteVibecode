# Функциональные пробелы APK — 4 октября 2026

Основание: текущие исходники APK 0.13.3, моста агента 0.4.2 и отчёты первой/второй очереди. Это сопоставление реализации; живые модельные задачи и опасные операции повторно не запускались. Старый FUNCTIONAL_GAPS.md относится к APK 0.11.2 и не отражает текущую готовность.

## Реализовано

Чат, модель/усилие, проекты и распределение чатов, Markdown и копирование, изображения и скачивание, файловые ссылки, передача, субагенты (просмотр/сообщения/остановка), вопросы и разрешения, остановка задачи, результаты и лимиты, уведомления, архив/названия/ветки/откат, поиск текущего чата, планы/цели, нативная очередь, базовые Git/review, ADB, привязка и обновления.

## Подтверждённые пробелы

| Приоритет | Область | Реализация и необходимое дополнение |
|---|---|---|
| P1 | Очередь и корректировка | steer_queued явно отказывает для nativeId. Телефон использует очередь Desktop либо моста в зависимости от overrides. Нужна согласованная доступность действий и проверенная безопасная корректировка нативной записи; нельзя заявлять атомарный перенос без поддержки API. Редактирование нативной очереди сейчас только текстовое. |
| P1 | Доступность файлов | workspace_list возвращает первые 200, без курсора. Скрываются все dotfiles, build, node_modules, __pycache__ и symlinks. Нужны пагинация, явный переключатель скрытых/служебных файлов и безопасное поведение для ссылок. Поиск APK фильтрует только открытую папку. |
| P1 | Совместимость | APK не получает общую версию протокола и набор возможностей моста в status. Нужна проверка совместимости и понятные disabled-состояния при старом агенте/Desktop. Для режима планирования уже используется объявленный список modes. |
| P2 | Поиск | Только thread/searchOccurrences текущего чата. Нет поиска содержимого по проекту/всем чатам. Реализацию общего поиска нужно согласовать с доступным API и ограничениями обхода истории. |
| P2 | Редактирование отправленных сообщений | Изменение есть для очереди, а действий редактировать уже отправленное сообщение/повторить ответ нет. Есть ветка и откат по ходу. Новый сценарий требует явной семантики продолжения истории и подтверждения расхода. |
| P2 | Git | status/diff, переключение существующих веток, stage всех файлов, commit и worktree add/list есть. Нет выбора файлов для stage/unstage, создания ветки, просмотра истории коммитов, удаления worktree и выбора диапазона review. Push/fetch/pull не реализованы; добавлять лишь отдельными явными действиями. |
| P2 | Файловые операции | Просмотр, скачивание, вложения, mkdir есть. Нет редактирования/сохранения текста, переименования, перемещения и удаления файлов с конфликтами и подтверждениями. Это расширение продукта, а не обязательный дефект. |
| Ограничение API | Создание субагентов | Прямой подтверждённый публичный RPC создания настоящего дочернего агента не найден в предыдущем исследовании. Поддержаны существующие агенты. Независимый thread/start нельзя выдавать за субагента. Повторно исследовать при изменении Desktop. |

## Дополнительные возможности продукта

Приём файлов/текста через Android «Поделиться», глобальный поиск файлов, голосовой ввод отдельной кнопкой. Сейчас соответствующих обработчиков ACTION_SEND/RECORD_AUDIO нет. Диктовка клавиатуры остаётся внешней возможностью Android. Эти предложения не относятся к обязательному переносу Desktop.

## Проверки, которые ещё нужны

Живые review, продолжение цели, планирование и корректировка нативной очереди; сценарии удаления записи очереди непосредственно на Desktop и восстановления телефона; новый мост через фактический маршрут телефона после отложенной активации; обновлённая Windows-сборка. Фоновый TaskWatchService использует START_NOT_STICKY, поэтому доставка после остановки процесса/перезагрузки телефона не гарантирована; механизм восстановления/инструкция нуждаются в отдельной проверке. Не обещать работу после force-stop.

4. Поиск по проекту и управление историей сообщений.
5. Выбор файлов для Git и дополнительные операции.
