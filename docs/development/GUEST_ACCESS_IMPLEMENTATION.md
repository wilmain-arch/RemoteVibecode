## Непроверенное и ограничения

- Живой запуск с авторизацией владельца, лимиты на реальном аккаунте и длительная нагрузка не проверены; модели не запускались ради проверки.
- Выполнение гостей только Linux; Desktop должен быть закрыт. Учёт округлённых глобальных счётчиков не обеспечивает точный процентный потолок и не атрибутирует внешнюю активность аккаунта.
- Общий дисковый бюджет — мониторинг, не жёсткая файловая квота. Ядерное ограничение размера отдельного файла и cgroup проверены отдельно.
- Не выполнены полный TalkBack-аудит, проверка всех инструментов, реальное сохранение через системный файловый диалог и жизненный цикл обновления авторизации. Проверка восстановления состояния Compose не равна полной проверке убийства процесса Android.
- Не подтверждён весь гостевой сценарий между двумя настоящими устройствами через рабочий ретранслятор. Маршруты и права проверены TLS-тестами; рабочая активация ожидает idle.
- Автоматический анализ code-reviewer нашёл структурный долг (крупный server.py, длинные функции); результаты не считаются оценкой безопасности или полноты API. OpenAPI-контракт отсутствует, формальная проверка совместимости схем не выполнена.

Предварительная версия не объявляется полностью готовой к публичному распространению.

# Гостевой доступ — состояние реализации

Дата: 2026-10-05. Локальная предварительная реализация; не опубликована.

## Готовый базовый слой

- SQLite-хранилище гостей, сессий, приглашений, прав и бюджетов отдельно от state.json владельца.
- Одноразовое приглашение на 30 минут (API позволяет 1 минуту — сутки).
- Ключ приглашения и ключ сессии сохраняются на мосте только в виде SHA-256. operationId защищает повтор создания; повтор принятия после потерянного ответа допустим только с прежним ключом устройства и сессии.
- Сессия гостя действует 30 суток; отзыв и изменение идентичности привязки владельца инвалидируют доступ.
- Окна fiveHours и week независимы: unlimited, fixed, renewing; база full или remaining.
- configure сохраняет расход; reallocate явно выделяет бюджет заново. Сброс одного окна не пополняет второе. Фиксированный расход сохраняется между окнами.
- Журнал задач считает дельты однократно, блокирует неоднозначный расход и параллельное измерение. **Журнал пока не подключён к запуску реальных задач.**
- Android: управление приглашениями, изменение квот, отправка ссылки, подтверждение отзыва, открытие приглашения в отдельном зашифрованном профиле без замены основной привязки.
- Linux-прототип exec-server в Bubblewrap: отдельные mount/PID/network namespaces, нет домашней папки владельца, чистое окружение, сброшенные capabilities, только собственная рабочая папка на запись.

## API

| Метод | Маршрут | Доступ |
|---|---|---|
| GET | /api/guests | Владелец |
| POST | /api/guests/invite | Владелец |
| POST | /api/guests/action | Владелец; configure/reallocate/revoke/grant/unshare |
| POST | /api/guest/redeem | Одноразовый секрет приглашения + deviceId + случайный sessionToken |
| GET | /api/guest/self | Гостевая сессия |

Все существующие маршруты владельца закрыты для гостевых токенов. Произвольный прокси RPC отсутствует.

## Что ещё не готово

**Гость пока не может работать с Codex. executionAvailable всегда false.**

- Подключение проверенного environment/add к рабочему гостевому маршруту и аккаунту владельца. Изолированный цикл модель → exec_command → результат уже проверен на синтетическом провайдере.
- Проверка всех инструментов и отсутствия локального fallback, отключение личных MCP/плагинов владельца.
- Общий планировщик владельца/гостей, обработка прямой активности Desktop, мониторинг квоты и остановка текущей задачи.
- Восстановление неоднозначного расхода после сбоя и контроль последовательности снимков провайдера.
- Собственные реальные проекты/чаты гостей. workspaceScopeId в guest/self сейчас только идентификатор будущей гостевой области, **не созданный проект Codex**.
- Предоставление истории, файлов и изображений по ACL. Сейчас права записываются, но гостевых маршрутов чтения этих ресурсов нет.
- Копии/worktrees, ветки общих чатов, просмотр и принятие изменений владельцем.
- Полноценное переключение гостевых подключений, QR-коды, ручное пополнение квот в UI и окончательный жизненный цикл приглашений.
- Защита от злоупотреблений, ограничения процессов/диска, очистка истёкших сессий/приглашений, миграции схемы.
- Проверка больших шрифтов, TalkBack и восстановления формы после принудительного завершения процесса.

## Второй этап: изолированное выполнение и устойчивая очередь

Реализованы локальные компоненты, пока не включённые в рабочий мост:

- `guest_executor_gateway.py`: WebSocket на loopback со случайным Bearer-ключом соединяет native environment Codex с exec-server внутри Bubblewrap. Гостю ключ не передаётся.
- `guest_jobs.py`: очередь в той же SQLite, привязанная к гостевой идентичности; стабильные operationId, проверка содержимого повтора, отмена, отзыв, последовательное получение задачи и блокировка неоднозначного запуска после перезапуска.
- `guest_scheduler.py`: последовательный диспетчер с внедряемыми исполнителем, счётчиком и проверкой занятости владельца. Исключение после резервирования оставляет задачу в uncertain, без автоматического повторного запуска.
- `GuestAccess.checkpoint`: промежуточный учёт расхода, сигнал исчерпания квоты; завершение считает только ещё не учтённую дельту. Смена окна или внешнее вмешательство блокирует дальнейшее измерение.
- CodexRpc допускает отдельные executable/env/cwd/config без изменения прежнего поведения владельца.

Проверено на установленном настоящем бинарнике Codex: environment/add, environment/info, thread/start и полный turn/start с exec_command через локальный синтетический Responses-провайдер. Команда увидела только тестовую гостевую рабочую папку; синтетический файл за её пределами недоступен. Авторизация владельца не использовалась, платных запросов не было.

Проверены повторы, чужие operationId, отзыв во время старта, отмена очереди, перезапуск, промежуточное списание без дублей, неоднозначный расход, приоритет владельца и потерянный ответ исполнителя.

**Ограничение:** диспетчер ещё не соединён с HTTP/API рабочего Bridge, Android и реальным провайдером. Проверка owner_idle пока внедряется тестом; мониторинг прямой активности Desktop, остановка реального хода при отзыве/исчерпании, все инструменты и отсутствие fallback требуют отдельной интеграции. Не является готовым гостевым запуском. Основной APK, мост и агент не обновлялись. WebSocket требует зависимости websockets; упаковка новой зависимости ещё не сделана.


## Продолжение: HTTP-очередь и исполнитель

- Bridge создаёт GuestJobs и восстанавливает неоднозначные задания при запуске.
- GET /api/guest/tasks: только собственные задания гостя.
- POST /api/guest/cancel: отмена собственного задания; неизвестный/чужой ID недоступен.
- POST /api/guest/send: проверяет гостевую сессию и возвращает 503 guest_execution_unavailable, пока runtime не подключён. Задача при этом не принимается и не запускается.
- Отзыв владельцем отменяет очередь и запрашивает остановку активной задачи. Повторная проверка отозванных идентичностей выполняется перед выдачей заданий и после перезапуска.
- GuestRunner подключает native environment, запускает/возобновляет thread, обрабатывает итоговые сообщения, проверяет checkpoint и вызывает turn/interrupt. Время ожидания подтверждения остановки ограничено 10 секундами; неполученный ответ приводит к uncertain. Закрытие RPC и gateway выполняется в finally.
- Личный HOME не наследуется; брокер задаётся отдельно. apps/hooks/plugins/remote_plugin/multi_agent выключаются параметрами процесса. Автоматического копирования авторизации нет.
- Проверен GuestRunner на реальном Codex с синтетическим Responses-провайдером: задача завершилась, exec_command выполнялся в /workspace, итоговый turn получен. TLS-тесты проверили отказ гостевого запуска без runtime и запрет владельцу использовать гостевые маршруты.

Остаются: рабочая интеграция общей очереди с send_lock владельца, обнаружение прямой активности Desktop, безопасное предоставление провайдерной авторизации приватному брокеру, длительный мониторинг и Android-экран гостевого чата. Реальная остановка по отзыву/квоте ещё не проверена на живом аккаунте. Production runtime не включён; APK и локальный агент не изменены.

## Исправление ложной блокировки Desktop

Проверка раньше считала ресурсы из `/usr/lib/chatgpt` признаком открытого Desktop. Процессы node_repl, cua и codex-code-mode-host запускаются также мостом. Исправлено: проверяется имя GUI executable ChatGPT/codex-desktop. Три регрессионных теста проверяют helper-процессы, настоящий GUI с переименованным потоком и отказ чтения proc. Полный прогон: 169 тестов. На рабочем ПК исправленная проверка возвращает false. Активация установленного модуля отложена до завершения текущей задачи; настоящее гостевое выполнение после неё ещё не подтверждено.

## Гостевая навигация и безопасное обновление

После закрытия гостевого экрана телефон без привязки владельца показывает сохранённые подключения. Жест назад из гостевого чата возвращает к информации подключения; доступ и токен не удаляются. Три GuestAccessUiTest прошли на USB, включая повторное открытие сохранённого профиля без owner pairing; жест назад отдельно инструментально не проверен. Основная APK обновлена с сохранением данных. Гостевая can_launch теперь учитывает update_until под общим send_lock; отдельный тест блокировки/release, полный Python прогон 170. У существующей гостевой задачи обнаружено uncertain/bridge_restarted; автоматический повтор запрещён, исход требует явного согласования владельцем. Исправление запуска установлено на диск, безопасная активация после текущей задачи с восстановлением предыдущего enabled; во время ожидания гостевой исполнитель временно выключен.
