# Создание нового плана

## План реализации

1. Использовать установленный collaborationMode/list и turn/start с режимом plan.
2. Добавить отдельный запуск с описанием задачи и явным подтверждением расхода лимита.
3. Сохранять идентификатор запроса до отправки; повтор возвращает квитанцию отправки.
4. Показывать текущий план отдельно, предыдущие — в раскрываемой истории.
5. Проверить защищённый HTTP API с имитацией Codex и собрать основную relay APK.

## Поведение

Инструменты чата → План и цель → Создать новый план. После запуска открывается чат. Режим следующего обычного сообщения не меняется. При активной задаче или непустой очереди запуск отклоняется. Планирование расходует лимиты только после подтверждения пользователем. История Codex сохраняется. Новые планы с Desktop также становятся текущими по порядку ходов.

## Проверка

- 58 тестов моста прошли. Проверены подтверждение запуска, повтор с тем же ID, конфликт содержимого, потерянный ответ, сохранение квитанции между контроллерами и выбор текущего плана по порядку ходов.
- Защищённый HTTPS API проверен с имитацией app-server: активная задача отклоняет новый запуск; успешный запуск отправляет collaborationMode=plan; повтор возвращает тот же turnId; обычный режим сохраняется.
- Установленный Codex через локальный защищённый мост объявляет plan и default. Живой платный запуск не выполнялся.
- assembleRelayDebug и assembleRelayDebugAndroidTest прошли с JDK 21. APK 0.13.2 (44), сертификат совпадает с существующим сертификатом обновлений.
- Добавлен Compose-тест текущего плана, раскрытия истории и повторной отправки с тем же operationId. Тест собран, на телефоне не запускался: ADB offline. Обе темы и крупный шрифт на телефоне в этой итерации не проверены.
- Агент Arch 0.4.1 установлен; controls.py и server.py сверены с исходниками. Перезапуск подготовлен через защищённую проверку простоя и очереди; активную задачу не прерывает.
- APK: outbox/RemoteVibecode-0.13.2-debug.apk. Пакет: outbox/remotevibecode-agent-0.4.1-1-any.pkg.tar.zst.
- Новые изменения не опубликованы в GitHub. Windows EXE в этой итерации не пересобирался; общий код моста обновлён в исходниках для всех систем.
- Модель и усилие наследуются из параметров текущего чата. Во вкладке показываются последние 10 опубликованных планов и последних 10 сводок, а полная история остаётся в Codex.


## Очистка вкладки — APK 0.13.3 / агент 0.4.2

После принятия нового плана мост сохраняет plan_boundaries[threadId]=turnId. Граница независима от ограниченного журнала квитанций. Вкладка показывает только текущий план; блок предыдущих планов удалён. Отмена и отказ не меняют границу. Потерянный ответ восстанавливается из квитанции отправки. Последующие планы Desktop учитываются по порядку ходов; другие чаты не затрагиваются. Если принятый ход ещё не появился в ответе Desktop, прежние планы не показываются.

Проверки: 62 теста моста, включая настоящий перезапуск тестового HTTPS-процесса, сохранение границы на диске, потерянный ответ, отсутствие повторного запуска, изоляцию чатов и план Desktop. Два Compose-теста прошли на OnePlus по USB в отдельном fixture-пакете: отмена, успех, ошибка, повтор с прежним operationId и обновление вкладки. Синтетический скриншот тёмной темы просмотрен. Fixture-пакеты удалены, системные настройки телефона не изменялись. Основная APK 0.13.3 (45) установлена с сохранением данных. Агент Arch 0.4.2 установлен; активация отложена до простоя через update/prepare. Живой платный запуск и обновлённый мост через маршрут телефона после активации пока не проверены. Изменения не опубликованы.
