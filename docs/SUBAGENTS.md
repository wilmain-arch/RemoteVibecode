# Субагенты

В верхней панели чата нажмите кнопку «Субагенты». Меню показывает агентов текущего чата и их вложенных агентов: имя, роль, задачу и состояние. Список обновляется каждые четыре секунды, пока меню открыто.

Нажмите карточку, чтобы открыть сообщения, ход работы и изображения агента. Кнопка «Показать ранние сообщения» загружает предыдущую часть истории. При обновлении лента остаётся на месте, если вы читаете старые сообщения; у конца ленты она следует за новыми сообщениями.

- **Корректировать** отправляет уточнение выполняющему задачу агенту.
- **Отправить** запускает новую задачу в чате свободного агента.
- **Остановить** запрашивает прерывание текущей задачи после подтверждения. Родительский агент может продолжить работу и отреагировать на остановку.

Если Desktop запрещает прямой ввод конкретному агенту, приложение сообщает об этом. Ошибка запроса сохраняет введённый текст; повторная отправка того же сообщения использует тот же идентификатор. При обрыве связи уже загруженные сообщения остаются видны.

Нужен актуальный агент ПК. Возможности зависят от протокола установленного Codex Desktop. Меню не создаёт новых субагентов самостоятельно.

## Оформление

Используются существующие цвета MaterialTheme для светлой и тёмной темы, иконки интерфейса и типографика приложения. Карточки без разделителей: радиус 20 dp, внутренний отступ 16 dp, расстояние 12 dp. Кнопки верхней панели имеют область 48 dp. Управление закреплено над клавиатурой; остановка доступна только из выбранного чата агента.

## API моста

Все запросы требуют существующий Bearer-токен сопряжения. Новые методы не меняют старые маршруты. Перед просмотром или управлением мост проверяет, что agentId входит в дерево указанного threadId.

- `GET /api/subagents?threadId=…` — список потомков.
- `GET /api/subagents/history?threadId=…&agentId=…&before=…` — история выбранного агента с курсором.
- `POST /api/subagents/action` — `threadId`, `agentId`, `action` (`send` / `interrupt`), `text`, `messageId`. Для отправки обязателен идентификатор сообщения. Уточнение адресуется конкретному активному turnId; завершившаяся задача не подменяется другой.
